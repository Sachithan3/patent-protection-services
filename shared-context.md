## Project in one paragraph

ClaimGuard AI (`patent-protection-services/`) is a FastAPI LegalTech backend for preliminary
patent infringement screening. It is being migrated from a static PostgreSQL/pgvector + seed-data
RAG design to an **agentic retrieval** design: provider adapters pull patents from public APIs at
request time, embeddings are computed in memory, a constrained agent loop plans/evaluates/refines
searches, a Gemini-only LLM track produces a risk report whose quotes are machine-verified, and a
job API + SSE streams progress. The full contract is the migration spec; this file tracks *actual
execution state* against it.

## Design notes / gotchas so far

- Spec's `dedupe_key` snippet crashes on unmatched IDs (`m["num"]` on `None`); implementation parses once via a shared `_parse()` helper that raises `ValueError` for both functions.
- Patent-ID regex from the spec does not cover design (D), plant (PP), reissue (RE) prefixes — documented as a known limitation in `ids.py`; unrecognized formats raise `ValueError` by design.
- `test_phase1.py` asserts the *old* world (pgvector in requirements, DB vars in `.env`); pytest is scoped to `tests/` so it stays uncollected until its Phase 2 rewrite.
- mypy is intentionally scoped to the new modules (`app/providers`, `app/core/ratelimit.py`, `app/core/ssrf.py`) with `ignore_missing_imports` — full-app typecheck needs the heavy deps installed and is deferred.
- Retry/backoff constants on the shared HTTP client are constructor-injectable so tests can shrink backoff to milliseconds.
